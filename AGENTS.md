
- Scheduling re-runs (evaluate/emit edge functions) skip months whose workflow stage is locked or published; override only with `force_locked=1`. Why: protects hand-edited, approved schedules from being overwritten.
- Oversupply trims in buildShiftRecommendationRows are week-balanced (cut from the fullest week, latest slot first within it); keep src/lib and _shared copies identical. Why: latest-first cutting emptied the end of the month for oversubmitted providers.
- Provider Directory Medallion data flows: pg_cron (main) -> sync-medallion-directory (main, writes only medallion_* tables + medallion_sync_runs) -> medallion-directory-fetch (scheduling backend, GET-only, holds MEDALLION_API_KEY). Why: the key lives only on the scheduling backend and the directory must never overwrite local profiles/agreements automatically.
- Medallion sync never treats "not returned" as termination; links providers only by exact Medallion ID; conflicts are stored, not applied. Why: inactive providers are hidden by Medallion's default list and their detail endpoints 404.
- Sync freshness is computed from last successful full apply run timestamps (computeEntityHealth), not self-reported job status. Why: detects jobs that never start.
- PCP telemedicine coverage comes from sync-pcp-coverage (own pg_cron job at 10:45+11:45 UTC gated to 5 AM Chicago, read-only native query, report_key pcp_coverage_by_provider_id) and links EHR provider IDs to profiles only by exact NPI (profile or linked Medallion record); names never establish identity. Why: sync-metabase dies mid-run so card 2940 stopped refreshing, and 2940 returns no provider IDs.
- External (agency) providers live in external_* tables keyed by agency + stable external ID; imports go through the dry-run diff in src/lib/externalImport.ts, never touch Medallion-linked records, local employment status or coverage, and blank cells never clear values. Why: agencies own external data, Medallion owns internal, Metabase owns coverage.
- Collab calendar state scope is read from saved meeting_attendees notes through collabMeetingStates; agreement links enrich only matching selected states with MD/chart details. Why: current agreements must not expand historical event selections.
- Collab chart links resolve through the shared spreadsheet library (system_config key collab_spreadsheet_library, src/lib/collabSpreadsheetLibrary.ts): a provider's selected states match a registered spreadsheet, and the meeting's Eastern month picks that month's tab link; agreement chart links remain the fallback for states with no library match. Why: one shared registry beats re-entering links per provider or per meeting.
- Collab chart tab mappings are shared in system_config and matched by saved attendee states plus Eastern meeting year/month; use existing agreement links only when a state has no matching mapped tab. Why: tabs are month-specific and shared across providers without changing agreement records.
- New-provider collaboration prompts resolve selected states against saved state compliance rules and provider profession; document-required wizard entry defaults to the completed-process path. Why: current rules govern uploads without sending repeat notifications.
